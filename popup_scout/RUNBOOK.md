# 리빙·유아동 팝업 데일리 — 실행 절차

매일 오전 7시대(한국 시간) 예약 작업이 이 절차를 그대로 따른다.
사규(`AI_COMPANY.md`) §1 절대 규칙과 §3-1 시장조사팀 기준을 따른다.

- 노션 상위 페이지: https://app.notion.com/p/41e3fbe4e44981b08468c0fa3f58cdfb (리빙·유아동 팝업 데일리)
- 하위 페이지 제목: `리빙·유아동 팝업 10 (YYYY-MM-DD)` — 날짜는 한국 날짜
- 작업 폴더: 스크래치패드 (후보 JSON, 중복 목록은 저장소에 커밋하지 않는다)

## 1. 기준일 정하기

`TZ=Asia/Seoul date +%F` 결과를 기준일로 쓴다. 상위 페이지에 같은 날짜 하위 페이지가 이미 있으면 새로 만들지 않고 멈춘다.

## 2. 최근 7일 중복 목록 만들기

상위 페이지를 열어 기준일 이전 7일치 하위 페이지를 읽는다. 각 페이지 맨 아래 "중복 체크용 키" 토글의 `브랜드 | 장소` 줄을 모아 `history.txt`에 한 줄씩 적는다. 페이지가 없으면 빈 파일로 둔다.

## 3. 후보 15~20개 수집

웹 검색으로 아래를 찾는다. 같은 검색어만 반복하지 말고 채널을 섞는다.

- 리빙: 가구, 인테리어, 홈데코, 조명, 주방·테이블웨어, 침구·패브릭, 향(캔들·디퓨저), 라이프스타일 편집샵
- 유아동: 키즈 패션·용품 브랜드, 완구, 캐릭터, 그림책·교구, 유아식·육아용품, 키즈 체험형 팝업
- 채널: 백화점(현대·신세계·롯데·갤러리아·AK), 복합몰(더현대·스타필드·IFC 등), 성수·한남·연남 등 스트리트 단독 팝업, 지방 거점(부산·대구·대전·광주 등), 리빙·베이비 페어는 '팝업' 성격이 분명할 때만
- 검색어 예: `리빙 팝업스토어 {월}월`, `키즈 팝업 오픈`, `성수 팝업 리빙`, `백화점 유아동 팝업`, `캐릭터 팝업 11월`, 각 백화점 이벤트·공지 페이지

후보마다 공식 출처(브랜드 공식 계정·홈페이지, 백화점·몰 공지, 보도자료)를 직접 열어 기간·장소를 확인한다.

- 확인되지 않은 칸은 지어내지 말고 `"미확인"`으로 적는다 (종료일은 `null`).
- 언론 기사만 있고 공식 출처가 없으면 `source_type`을 `"언론 보도"`로 적는다. 코드가 자동으로 제외한다.
- 오픈일을 공식 출처에서 확인하지 못하면 후보에 넣지 않는다.

후보를 `popup_scout.py` 맨 위 설명에 적힌 JSON 형식으로 `candidates.json`에 저장한다. `summary`·`why_now`는 사규 §2 브랜드 기준(금칙어 금지, 단정한 큐레이터 어조, 숫자는 아라비아 숫자)을 지킨다.

## 4. 검증

```
python3 popup_scout/popup_scout.py check --candidates candidates.json --today 기준일 --history history.txt
```

통과가 10개 미만이면 3단계로 돌아가 후보를 더 찾는다. 두 번 보충해도 모자라면 모자란 채로 진행한다. 기준 미달 건으로 채우지 않는다.

## 5. 노션 페이지 만들기

```
python3 popup_scout/popup_scout.py render --candidates candidates.json --today 기준일 --history history.txt > page.md
```

`page.md` 내용을 그대로 본문으로, 상위 페이지 아래에 하위 페이지를 만든다. 아이콘은 🛋️.

## 6. 보고

마지막 답변에 아래만 짧게 적는다.

- 만든 노션 페이지 링크
- 리빙 n개 / 유아동 n개, 10개 미달이면 그 사실
- 실패한 단계가 있으면 어디서 왜 실패했는지 (실패를 성공으로 보고하지 않는다)

메일 발송, SNS 게시, 결제는 하지 않는다. 저장소에는 커밋하지 않는다.
